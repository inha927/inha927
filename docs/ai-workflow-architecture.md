# AI 협업 워크플로 설계 — 종합 검토 결과

> 2026-08-16 · 검토 대상: 여러 프로젝트 × 여러 AI × 여러 기기

## 결론: 3계층으로 나눈다

| 계층 | 성격 | 위치 | 공통/구분 |
|---|---|---|---|
| **방법** (커맨드·협업 규칙) | 거의 안 변함 | `AGENTS.md` + `.claude/commands/` | **공통** |
| **지식** (UEFN·Verse 검증 사실) | 천천히 변함 | claude.ai 스킬 (`freeze-tag-uefn`의 knowledge) | **공통** |
| **상태** (진행·수치·결정·테스트) | 매일 변함 | **각 프로젝트 파일** | **프로젝트별 구분. 절대 섞지 않는다** |

상태를 공통으로 두면 프로젝트끼리 오염되고, 방법을 프로젝트별로 두면 규칙이 갈라진다. 경계는 "변하는 속도"다.

## 프로젝트별 판정

### 플라이 이스케이프 — 기존 체계 유지. DEV_STATE.md 추가 금지

아티팩트 현황판(92f37c04…)을 열어 확인한 결과, 프로젝트 폴더에 이미 완성된 정본 체계가 있다 [확인: 아티팩트 본문]:

```
UEFN 프로젝트 폴더/
├ AGENTS.md              ← 작업 규칙 + §4.1 오판 9건 재발 방지
└ Docs/
  ├ README.md            ← 정본 색인
  ├ 인수인계_YYYY-MM-DD.md ← 진행 상태 (= DEV_STATE 역할)
  ├ 테스트 기록.md         ← PASS/FAIL 유일 소유
  └ AI 작업 잠금/          ← 다중 AI 동시 작업 잠금
```

이건 DEV_STATE.md보다 정교하다. **여기에 DEV_STATE.md를 추가하면 정본이 둘이 되어 체계가 죽는다.** `/dev-state`·`/resume` 커맨드가 이 형태("정본형")를 인식해서 인수인계 문서를 갱신하도록 만들었다.

**아티팩트의 역할 = 사람용 대시보드.** 아티팩트 스스로 "이 페이지는 읽기용 스냅숏, 정본은 프로젝트 안"이라 선언하고 있고, 그게 맞다. 다른 AI(GPT 등)는 아티팩트를 읽지도 쓰지도 못하므로 아티팩트를 정본으로 삼는 순간 다중 AI 협업이 깨진다. 계속 쓰되 역할 고정: **AI가 읽고 쓰는 곳 = 프로젝트 파일 / 사용자가 폰·웹에서 보는 곳 = 아티팩트.**

## 기기·계정 전역 적용 지도

"동일 계정이면 어디서나 같은 지침"을 만드는 실제 경로는 4개다. 이 환경(클라우드 컨테이너)은 세션이 끝나면 사라지므로, **여기 로컬에 저장하는 건 영속이 아니다** — 아래만이 영속이다.

| 경로 | 적용 범위 | 상태 |
|---|---|---|
| **이 레포의 `AGENTS.md`** | 레포를 여는 모든 도구. Codex·Cursor는 AGENTS.md 자동 인식, Claude Code는 `CLAUDE.md → @AGENTS.md`로 로드 | ✅ 완료 (이 커밋) |
| **claude.ai 스킬** | 같은 계정의 모든 Claude 채팅·Claude Code 세션 (freeze-tag-uefn이 이미 이 방식으로 동기화되는 걸 확인) | ⏳ 사용자가 claude.ai에서 스킬에 프로토콜 요약 추가 |
| **claude.ai 개인 설정(프로필 선호)** | 같은 계정 전역, 한 줄짜리 | ⏳ 사용자가 붙여넣기 |
| **PC `%USERPROFILE%\.claude\`** | 그 PC의 모든 폴더 (VS Code·CLI·앱 공통) | ⏳ PC당 1회 설치 |

### PC 1회 설치 (Windows)

```bat
mkdir %USERPROFILE%\.claude\commands
:: 이 레포의 .claude\commands\dev-state.md, resume.md 를 위 폴더로 복사
:: 이 레포의 AGENTS.md 를 %USERPROFILE%\.claude\CLAUDE.md 끝에 붙이거나,
::   각 프로젝트 폴더에 AGENTS.md 로 복사
```

### GPT 등 다른 AI에게

메모리·프로젝트 지침에 레포의 `AGENTS.md` 전문을 붙여넣는다. 파일을 읽을 수 있는 도구(Codex CLI 등)는 작업 폴더의 `AGENTS.md`를 자동으로 읽으므로 프로젝트 폴더에 파일만 있으면 된다.

## 클라우드 세션의 한계 [확인: 이 세션에서 실측]

플라이 이스케이프 프로젝트 파일은 GitHub에 없고 UEFN Revision Control로만 동기화된다. 따라서 **클라우드 Claude(웹·모바일)는 그 파일을 읽을 수 없고, 아티팩트(읽기 전용)만 볼 수 있다.** 클라우드/폰에서도 플라이 이스케이프 문서 작업을 하고 싶어지면 그때 `Docs/`만 private 레포로 미러링한다 — 지금은 불필요해서 만들지 않았다.

## 이번에 만들지 않은 것과 이유

- **새 private 레포** — 채울 내용(플라이 이스케이프 Docs)이 PC에만 있어 여기서 만들면 빈 껍데기다. 필요 시점에 만든다.
- **아티팩트 수정** — 현황판은 이미 자기 역할(스냅숏)을 정확히 선언하고 있고, PC의 Claude가 관리 중이다. 손대면 오히려 그쪽 흐름을 깬다.
- **스킬 직접 수정** — 스킬은 claude.ai에서 계정으로 관리된다. 여기서 로컬 복사본을 고쳐도 동기화되지 않는다.
