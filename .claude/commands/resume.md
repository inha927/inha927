# 이어서 개발 (/resume)

표준 시작 문구의 실행형이다:
> 프로젝트 루트의 `AGENTS.md`와 `DEV_STATE.md`를 읽고, 잠금을 확인한 뒤 DEV_STATE의 다음 단계부터 계속해.

## 순서

1. **루트 `AGENTS.md`를 읽는다** — 그 프로젝트의 작업 규칙. 없으면 공통 프로토콜 포인터 한 줄짜리로 만들고 시작한다 (공통 프로토콜 §1)
2. **루트 `DEV_STATE.md`를 읽는다** — 없으면 표준 형식 골격으로 만들고, "지금 목표"를 사용자에게 확인한다
3. **잠금 확인** — `Docs/AI 작업 잠금/`이 있으면 `status: "ACTIVE"` 파일을 찾는다. 있으면 그 영역은 건드리지 않는다
4. **문서와 실제 대조** — git이면 `git status`·`git log --oneline -10`, 그리고 "핵심 파일" 경로가 실존하는지. 어긋나면 **실제가 정답** — 어긋난 지점을 먼저 보고한다
5. **시작 로드는 여기까지.** `Docs/`의 심층 문서(스펙·테스트 기록·역사)는 그 값이 필요해질 때만 연다

## 그다음

1. 3줄로 요약한다: 어디까지 됐나 / 왜 이 방식인가 / 다음 할 일
2. **"다음 할 일" 첫 항목부터 시작한다.** 큰 결정(공통 프로토콜 기준: 게임 규칙 변경, 일정·목적 변경 등)이 끼어 있으면 그것만 묻고, 아니면 진행한다
3. **"실패한 접근"·"폐기" 목록의 방법은 재시도 금지.** 되살릴 이유가 생겼다면 그 이유부터 사용자에게
4. 작업을 마치면 `/dev-state`로 세션을 닫는다
