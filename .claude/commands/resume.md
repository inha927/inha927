# 이어서 개발

## 0. 프로젝트 형태 판별

| 형태 | 판별 | 읽는 순서 |
|---|---|---|
| **A. 정본형** | 루트에 `AGENTS.md` + `Docs/` | 아래 A절 |
| **B. 단일형** | 루트에 `DEV_STATE.md` | 아래 B절 |
| **C. 없음** | 둘 다 없음 | 그렇게 말하고 `/dev-state`를 먼저 돌릴지 묻는다 |

## A. 정본형 (예: 플라이 이스케이프 UEFN 프로젝트)

이 순서대로 읽는다. 건너뛰지 않는다.

```
1. AGENTS.md               — 작업 규칙. 특히 오판 재발 방지 절차
2. Docs/README.md          — 어느 문서가 무엇의 정본인지 색인
3. 인수인계 문서의 최신 절   — 지금 어디까지 왔고 다음이 무엇인지
4. 테스트 기록.md 최신 절    — 실기 PASS/FAIL. 인수인계보다 우선한다
5. Docs/AI 작업 잠금/       — status: "ACTIVE" 있으면 그 영역은 다른 AI 작업 중
```

수치가 필요하면 실행 스펙을, UI 작업이면 해당 폴더 지침을 그때 연다.

## B. 단일형

1. `DEV_STATE.md`를 읽는다
2. **문서와 실제를 대조한다** — `git status`, `git log --oneline -10`, "핵심 파일" 경로 실존 확인. 어긋나면 **실제가 정답**이고, 어긋난 지점을 먼저 보고한다

## 공통 — 그다음

1. 3줄로 요약한다: 어디까지 됐나 / 왜 이 방식인가 / 다음 할 일
2. "다음 할 일" 첫 항목부터 시작한다. 큰 결정이 끼어 있으면 그것만 묻고, 아니면 진행한다
3. **"실패한 접근"·"폐기" 목록에 있는 방법은 다시 시도하지 않는다.** 되살릴 이유가 생겼다면 그 이유부터 말한다
4. 작업을 마치면 `/dev-state`로 상태를 갱신한다
